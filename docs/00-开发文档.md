# Melody — 开发文档

> 第三方网易云音乐客户端 · Android 手机 / 平板自适应
> 参照 [Melodia](https://github.com/rinchao0721/Melodia) 的功能点，UI 用 Jetpack Compose 从零编写。
> 开发节奏：**一步一步来，跑通一个功能再进入下一个**，每一步开始前与需求方确认。

---

## 一、项目定位

| 项 | 说明 |
| --- | --- |
| 目标 | 一个可用的第三方网易云音乐客户端（学习 / 个人使用） |
| UI | Jetpack Compose + Material 3，单 Activity，从零手写（不照抄 Melodia 的 UI） |
| 形态 | 手机 / 平板自适应（平板走双栏 / 分栏布局） |
| 数据源 | 网易云第三方 API（weapi 加密 + 账号登录） |
| 开发方式 | 单模块起步，跑通一个功能再下一步，稳定后再评估拆多模块 |

> 免责声明：本项目与网易云音乐及其运营方无关，仅调用使用者本人有权访问的数据，不破解会员、不绕过 DRM、不提供未授权下载。

## 二、功能清单（参照 Melodia）

按"先跑通听歌闭环，再铺内容，最后补进阶"的顺序分层：

### P0 · 地基
- 工程骨架（能编译、能装、能启动空页面）
- 设计系统（主题 / 深色 / 动效常量 / 基础组件）

### P1 · 听歌闭环（核心）
- 数据层：领域模型、网络层（weapi 加密 + OkHttp + 统一错误 `AppError`）、Room + DataStore、登录鉴权
- 播放内核：Media3 服务（后台 / 通知栏 / 耳机控制）、队列（顺序 / 随机 / 单曲）、进度、歌词解析
- 播放页：全屏播放器（封面 / 歌词 / 进度 / 控制）+ 迷你播放条
- 主框架：底栏导航 + 首页聚合流 + 搜索 + 歌单/专辑详情

### P2 · 用户体系
- 登录（手机验证码 / Cookie / 二维码）
- 我的 / 个人主页（用户信息 + 听歌排行）
- 音乐库（歌单 / 收藏 / 最近播放）
- 最近播放、听歌数据统计、关注歌手

### P3 · 进阶
- 评论（只读列表 + 最热/最新排序已上线；点赞/回复/楼中楼/发表因服务端设备风控暂缓）、消息中心
- 歌手主页、新歌首发、电台播客、云盘
- 歌单创建 / 编辑、歌曲下载、应用内更新、设置、内容过滤

## 三、技术栈

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 语言 / UI | Kotlin + Jetpack Compose + Material 3 | 用最新稳定版 Compose BOM |
| DI | Hilt | 编译期依赖注入 |
| 网络 | OkHttp 直连 + weapi 加密 | 不引入 Retrofit，拦截器管线更可控 |
| 序列化 | kotlinx.serialization | @Serializable |
| 本地存储 | Room（结构化数据）+ DataStore（配置 / 会话） | 会话凭证进 Android Keystore |
| 媒体 | Media3 / ExoPlayer | MediaSessionService 后台播放 |
| 图片 | Coil | |
| 构建 | AGP + Gradle + JDK 21 | minSdk 26，target/compileSdk 取最新稳定 |
| 加密 | BouncyCastle | 网易云 weapi 参数加密 |

> 具体版本号在**每个阶段开始时用官方渠道确认最新稳定版**，不在本文档写死，避免过期。

## 四、架构与目录组织

单模块 `:app` 起步，内部按职责分包（后续稳定再抽多模块，目录天然可迁移）：

```
app/src/main/java/com/melody/
├── MelodyApp.kt            # Application：Hilt 初始化、Coil 预热
├── MainActivity.kt         # 单 Activity
├── ui/                     # 设计系统 + 通用组件 + 主题
├── navigation/             # 类型安全路由定义
├── core/
│   ├── model/              # 领域模型
│   ├── network/            # OkHttp + 加密 + AppError
│   ├── database/           # Room
│   ├── datastore/          # DataStore + 会话
│   ├── media/              # Media3 播放服务 + 队列
│   └── lyric/              # 歌词解析
└── feature/
    ├── home/               # 首页聚合流
    ├── search/             # 搜索
    ├── player/             # 播放页 + 迷你条
    ├── playlist/           # 歌单/专辑详情
    ├── artist/             # 歌手主页
    ├── library/            # 音乐库 / 我的
    ├── profile/            # 个人主页
    ├── account/            # 登录
    ├── comment/            # 评论
    ├── message/            # 消息中心
    ├── podcast/            # 播客
    ├── cloud/              # 云盘
    ├── recent/             # 最近播放
    ├── listendata/         # 听歌数据
    ├── download/           # 下载
    ├── update/             # 应用内更新
    └── settings/           # 设置
```

依赖方向：`feature → core → ui`，`ui` 是叶子，`core` 不依赖 `feature`。

## 六、开发约定

1. **每步先确认再动手**：进入每个阶段 / 每个具体任务前，先说明「要做什么、产出什么、怎么验收」，得到确认后执行。
2. **验收 = 能跑起来看到效果**：任何时刻中断，项目都处于可运行状态。
3. **版本在阶段开始时确认**：不沿用过期版本号，每个阶段动手前用官方渠道核对最新稳定版。
4. **错误模型统一**：网络 / 数据边界统一返回 `Result<T>`，异常归一为 `AppError`（网络中断 / 风控 / 鉴权过期 / 解析失败 / 业务错误码）。
5. **错状态分开**：「未登录」≠「加载失败」，前者给登录引导，后者给重试。
6. **动效参数集中**：时长 / 曲线 / 按压档位统一放 `Motion.kt`，不散落硬编码。

### 阶段 7 · 功能框架补齐 ✅（2026-09-26 真机验证通过）

> 原则：**先把框架铺完，再优化细节**。本阶段只做能跑通的整页 + 入口，不做交互动效与边界打磨。

- **新增**：

  - `CloudRepository`：云盘 `/weapi/v1/cloud/get`（body `{limit,offset}`，`data[]` 优先取 `simpleSong`，无则降级平铺字段 `songId/songName/artist/album`）

  - `toplist/ToplistScreen` + `ToplistViewModel`：榜单列表；点榜单把榜单 id 当歌单 id 打开**现有歌单详情**（复用，零新详情页）
  - `MainScreen` 覆盖层扩到 10 层（新增 Daily/Cloud/Toplist），返回键逐层关闭；`HomeScreen` 顶部加**快速入口行**（每日推荐/排行榜/云盘）

#### 补充 · 播放模式 + 新歌首发（s9，2026-09-26 真机验证通过）

- **播放模式**（`PlayerQueue` + `NowPlayingScreen`）：
  - `RepeatMode` 枚举 `ALL / ONE / OFF`，默认列表循环；`QueueState` 加 `shuffle` / `repeatMode`
  - `neighborIndex()` 统一算相邻下标：随机模式任选非当前曲；越界时列表循环回绕、顺序播放停
  - `playNext(auto=true)` 供 `STATE_ENDED` 自动续播：单曲循环时 `seekTo(0)` 重播本首；手动点下一首仍真切歌
  - `toggleShuffle()` / `cycleRepeatMode()`（列表循环 → 单曲循环 → 顺序）
  - 播放页控制行扩为五按钮（随机 | 上一首 | 播放/暂停 | 下一首 | 循环），激活高亮 `primary`，顺序播放/随机关为 `onSurfaceVariant`
- **新歌首发**：`DiscoverRepository.newSongs(areaId=0, limit=30)` → `/api/v1/discovery/new/songs`（body `{areaId, total, limit, offset}`），返回顶层 `data[]`（实发 100 首）；`NewSongsViewModel` 与每日推荐同构；首页快速入口扩为五卡（3+2：每日推荐/排行榜/新歌 + 云盘/播客）
- **验证**：新歌入口 → 列表 100 首（田馥甄/辉子…）→ 点第一首起播 `PLAYING` → 全屏页开随机 → 点下一首随机跳曲（第 1 首直接跳「圆月」，跳过顺序第 2 首）→ 循环模式三态轮换正常 → 切单曲循环、进度拖到结尾，`STATE_ENDED` 后重播本首（position 回落 0:21、歌名时长不变）；返回桌面再进 app 播放不中断
- 验收截图：`docs/phase9-modes.png`（全屏播放页，随机+单曲循环激活）

#### 补充 · 评论回滚为只读（s10，2026-09-26）

- **背景**：评论交互（点赞/回复/发表/楼中楼）上线后，真机自测发现所有写操作被服务端**设备风控**拦截（返回「系统检测到您的设备存在安全风险」，music.163.com 与 interface.music.163.com 域名一致），带 csrf/Referer 的 weapi 请求也不放行；列表读接口不受影响。
- **决策**：写操作全部回滚，**保留只读列表**（排序 + 分页 + 浏览），避免带故障能力的功能上线。
- **回滚面**：`CommentRepository` 只留 V2 列表接口；`Comment` 模型删 `likedByMe`/`replyCount`；`CommentViewModel` 删点赞/回复/发表状态机；`CommentSheet` 删输入栏/楼中楼/点赞交互；`NeteaseClient` 删 `csrfToken`/`INTERFACE_HOST`/Referer 注入；`CookieStore` 删 `cookieValue()`。
- **验证**：歌单评论（总数 117 万、最热/最新页签切换生效、纯展示赞数）+ 播放页歌曲评论正常展示；面板高度改按 `LocalConfiguration.screenHeightDp * 0.9f` 固定（`ModalBottomSheet` 内 `weight` 拿不到屏高导致列表不滚动）。

#### 补充 · 启动直达 + 播放页 AMLL 化（s11，2026-09-26 真机验证通过）

- **交互调整**：App 启动跳过登录页直达首页（登录态过期再自动跳登录）；首页移除「我的歌单」区（与「我的」页重复）；歌单/列表点歌直接打开全屏播放页。

- **歌词页（`AmllLyricsPage`）**：当前行 22sp 加粗 + primary 辉光 `Shadow`、未唱行 0.88 缩放 0.5 透明度、唱过行 0.3，`spring` 弹簧过渡；当前行自动滚到视口上 1/4；点行 seek；原文+翻译两行。
